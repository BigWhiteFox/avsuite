## 与既有叙事对账

- 「AEC 32ms + NR 32ms = 64ms」(core/README.md L28 语境、INTERVIEW-WP10.5-capstone.md L8)
  = 两级窗长之和(本表 #3 + #8),推算成立;加实测计算 ≈2.8 ms → **≈67 ms**,叙事自洽。
- capstone Q2「+ 帧缓冲 ≈ 70–80ms 端到端」:实测缓冲/对齐项为 0(#5)、计算仅
  ≈2.8 ms,预算落在 ≈67–69 ms,处于既有区间下段——原「帧缓冲」余量按实测收缩。
- 易混项澄清:streaming.py L5「感受野 12 帧 ≈ 240ms」是卷积**感受野**(回声路径
  建模长度),不是时延项,勿混入本表。

## 口径注意

1. lookahead 口径 = 仓内约定 n_fft−hop(帧右端样本到齐才出帧,输出前沿滞后输入):
   AEC 12 ms、GTCRN 16 ms;合计按窗长(32+32 ms,逐样本最坏)入账,偏保守。
2. AEC 计算主数字取 **torch 单线程**(与仓内 RTF「CPU 单线程」口径一致,且对
   并行训练负载最不敏感);默认 8 线程数并列供参考。
3. NR 两行口径如实分列:capstone 的 run_nr 是**整段批处理**(非流式);流式行是
   「若切全流式」的预算——单帧耗时合法(时间因果已单测),但 GRU 状态缓存实现
   来自官方 stream/,本仓未部署。
4. p99 判读:两级计算 p99(3.68 / 0.89 ms,首测;低负载复测@02:12 为 2.95 / 0.80 ms)均远低于各自帧预算(20 / 16 ms),
   本次测量未触发异常;若背景负载升高,p99 首先劣化,复测时先看它。
