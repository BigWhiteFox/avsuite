# INTERVIEW — WP-05a GTCRN + ONNX + INT8（模块5a）

## 3 分钟讲解提纲

**第 1 分钟：为什么是 GTCRN——端侧增强的约束三角**
- 车载/DSP 部署三约束：算力（<1 GMACs/帧级预算）、内存（KB 级权重）、时延（20ms 帧）
- GTCRN 答案：23.67K 可训练参数、33 MMACs、时间因果——比 DCCRN(3.7M) 小 150 倍
  还能打（论文 VCTK-DEMAND PESQ 2.87 / DNS3 盲测 DNSMOS OVRL 2.70），靠三个设计：ERB 频带压缩、分组卷积/GRU、
  双路 RNN 只在压缩域跑
- 我完成了官方权重移植 → ONNX 导出（对拍 6.3e-6）→ CPU 基准（RTF 0.0084、
  单帧 0.67ms）→ INT8 PTQ 全链路

**第 2 分钟：ERB 为什么能当轻量化折中（必含概念卡）**
- 人耳频率分辨率非均匀：低频敏锐（<500Hz 近似线性分辨）、高频迟钝（>4kHz 临界
  带宽按 ~20% 比例增长）——ERB(Equivalent Rectangular Bandwidth) 刻度按听觉
  临界带划分：GTCRN 前 65 bin（≈0-2kHz）原样保留，2kHz 以上 192 bin 压到 64 个
  ERB 带 → 频率维 257→129，网络一半的算力花在刀刃（低频谐波区）上
- 掩码仍在 ERB 域预测、经 ierb 线性展开回 257 bin 乘谱——高频掩码平滑是符合
  听觉的近似（高频本来就该宽带处理）
- 代价：高频精细结构（齿音/音乐泛音）处理粗——语音任务几乎无损，音乐增强不适用

**第 3 分钟：INT8 定点化——PTQ vs QAT（必含概念卡）+ 我的负面结果**
- PTQ（训练后量化）：拿预训练权重直接量化。静态版需校准集统计激活范围插 QDQ 节点；
  动态版激活运行时算 scale、只量化权重。优点零训练成本，缺点对分布外激活敏感
- QAT（量化感知训练）：训练/微调时插入伪量化节点（前向量化-反量化、反向 STE
  直通梯度），让权重学会适应量化格点。精度高，成本是要数据和训练
- **我的实测**：23.67K GTCRN 静态 QDQ 直接崩坏（SI-SNR 11.5→-20.8）——
  GRU 递归状态逐帧累积量化误差 + 小模型无冗余吸收量化噪声 + LayerNorm/Tanh
  scale 敏感；动态量化只掉 0.067 PESQ 可用。结论：越小越循环的模型越不能裸静态
  量化，量产走 QAT 或混合精度（GRU fp16 / Conv int8）
- 部署侧另一课：dynamic 量化提速仅 8%——小模型瓶颈在 Conv 算子调度不在权重带宽，
  真正的嵌入式收益要靠 NPU 工具链的静态图定点（不是 ORT CPU 的 QDQ）

## 高频追问预案

**Q1 ONNX 导出后怎么保证没导错？**
对拍纪律：同输入 PyTorch vs ORT 输出 max|diff|（DoD <1e-4，实测 6.3e-6 = fp32 舍入
量级）；再加时间因果性测试（扰动未来帧过去帧逐位不变）锁住结构语义。onnxsim
简化只折叠常量/消冗余节点，语义不变——简化后重新对拍。

**Q2 单帧时延怎么测的？为什么 T=1 调用合法？**
GTCRN 时间维严格因果（GTConv 时间只左 padding、inter-GRU 单向）——单测验证过。
所以 T=1 逐帧调用输出与整段调用在对应帧一致（差一个 GRU 状态：官方 stream/ 版
把状态外置传入，我的测法是"无状态单帧"= 计算量上界估计）。0.673ms/帧 vs 16ms
帧移 → 23.8× 余量，8 核 DSP 上单核足够。

**Q3 23.67K 为什么还留 24.6K 的 ERB 表？**
ERB 滤波器组是固定查表（requires_grad=False），不学习、可折进部署固件的 ROM，
不占运行时内存预算——论文口径只算可训练参数。我把两个口径都锁进单测
（可训练 23669 / 总 48245），防止口径混淆。

**Q4 GTCRN vs DCCRN 精度差多少？什么时候选谁？**
DNS 基准：DCCRN ~2.68（论文），GTCRN 论文 VCTK-DEMAND PESQ 2.87 / DNS3 盲测 DNSMOS OVRL 2.70（2024，训练配方也新了 4 年），自仓 fp32 实测 1.869（自混 held-out，更难）——
GTCRN 不是"牺牲精度换大小"，是架构+配方双进步。选型叙事：云端离线修复用
大模型（MP-SENet 级），端侧实时用 GTCRN 级；中间地带（车机 SoC 有 NPU）可以
上 DCCRN 量化版。我们仓库两个都有、指标都可复现，这是讲谱系的最好素材。

**Q5 为什么 hop 256 不是 320？车载 20ms 帧移怎么办？**
官方配方 hop=256（16ms）——帧移与算法时延 32ms（窗长）。车载规范若要求 20ms
帧（320 hop），需重训（STFT 参数进了模型结构：ERB 表/F 维绑定 n_fft，hop 只影响
T 密度，理论上可 320 重导出但精度未验证——诚实答案：以官方 256 为准，20ms 需求
走重训或用 WP-05b 流式 cache 方案对齐节拍）。

**Q6 RSS 354MB 是怎么回事？端侧内存怎么算？**
那是 Python 进程（ORT runtime + torch + numpy 全家）的增量，不是模型内存。
端侧口径：权重 240KB(int8)/290KB(fp32) + 激活工作区（129×16 特征图 × 层数 ≈
数百 KB）+ GRU 状态（KB 级）——总 <2MB，任何 MCU 都放得下。报告内存必须报口径。

**Q7 量化后单条最大掉点 1.76 PESQ 说明什么？**
dynamic PTQ 的尾部风险：个别 clip 激活分布撞上量化格点空洞（低能量帧的 scale
被高能量帧带偏）。量产要报分位数不只报均值（我们 CSV 留了逐条明细），
尾部敏感的座舱场景用 per-channel/per-frame scale 或 QAT 收掉。

## 必默写
- ERB 映射：`erb(f) = 21.4·log10(0.00437f + 1)`
- 复杂度账：GTCRN 33 MMACs vs DCCRN ~4.3 GMACs(4s)——差 100 倍的来源要能拆
  （F 维 257→129、通道 128→16、时间不降采样但特征小）
- PTQ/QAT 一句话：PTQ 快而脆（校准集定生死），QAT 稳而贵（要训练回路）
