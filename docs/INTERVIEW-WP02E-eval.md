# INTERVIEW — WP-02E 评估指标（模块2.5）

## 3 分钟讲解提纲

**第 1 分钟：指标分三类，各管各的问题**
- 有参考波形/谱：PESQ（感知质量）、STOI（可懂度）、SI-SNR（信噪比）——增强/分离任务
- 无参考：DNSMOS（MOS 预测）——真实场景没有 clean 参考
- AEC 专属：ERLE（回声抑制量）、AECMOS（回声消除质量 MOS）——看的是"回声漏没漏"和"近端损没损"，两个维度分开评

**第 2 分钟：PESQ 与 STOI 的一句话原理**
- PESQ（ITU P.862，wb=P.862.2）：时间对齐 → 听觉变换（响度表示）→ 双向（正向/负向）失真积分 → 映射 0.5~4.5。它是"对齐后的感知失真"，不是纯波形误差
- STOI：1/3 倍频程带 × 短时段的包络互相关（0~1），与人类可懂度得分高相关；对非线性处理比 PESQ 更敏感

**第 3 分钟：口径纪律（最容易翻车的地方）**
- 报任何数必带：采样率（PESQ wb 强制 16k）、wb/nb 模式、测试集构造（合成/真实、SNR 分布）、分场景统计
- 长度对齐约定：截断到较短者、不补零（padding 段会污染指标）
- 我的库：`core/evaluate.py` 统一 16k 重采样 + 文件名配对 + 静音 NaN 处理，全项目共用一套协议

## 高频追问预案

**Q1 PESQ 大概分数段是什么概念？**
带噪原始语音 5dB 白噪声 ≈ 1.0-1.5；理想带限 ≈ 3.5+；VoiceBank-DEMAND 上现代模型 2.9-3.2，早期 CRN ≈ 2.74；wb 上限 4.5 左右。报数时必须带测试集名。

**Q2 为什么无参考场景不能用 PESQ/STOI？**
两者都需要 clean 参考（对齐 + 失真计算）。真实录音没有参考 → 用 DNSMOS（微软 DNS-Challenge，三个 MOS 预测分 SIG/BAK/OVRL）或主观 MOS。Gradio demo 里我们只放 DNSMOS。

**Q3 ERLE 是什么？为什么只统计远端单讲段？**
ERLE = 10log10( Σ mic² / Σ err² )，在远端单独说话段统计——衡量"回声被消掉多少"。双讲段 mic 里混着近端语音，直接算 ERLE 会把近端当残余回声，数字无意义。双讲段要用 PESQ/AECMOS 评近端保真。

**Q4 AECMOS 是什么？**
微软 AEC-Challenge 的 MOS 预测模型（2021），三分量：SIG（近端语音质量）/ BAK（背景舒适度）/ ECM（回声抑制质量）。对双讲场景的评估比 ERLE+PESQ 组合更贴近听感。官方脚本就在 AEC-Challenge 仓库里（本机已克隆）。

**Q5 这些指标会打架吗？举个例子。**
会，我实测过：经典谱减在 5dB 噪声下 SI-SNR 4.95→14.02（大涨）但 STOI 0.573→0.483（反降）——SNR 指标看到"噪声能量少了"，STOI 看到"音乐噪声伤了包络结构"。结论：指标必须成组看，且以感知指标（PESQ/STOI）为主。

**Q6 PESQ 的局限？**
① 需要参考；② 对强非线性处理（如 aggressive NR）会失真地低估——它假设线性滤波+加性噪声；③ 对相位不直接敏感；④ 合成信号（非真语音）上不可靠——我的单测用共振峰合成信号驱动它，只验证单调性，不解读绝对值。

**Q7 为什么统一 16k 重采样？**
模型协议一致（16k 训练）；PESQ wb 强制 16k；车载电话链路常见 16k。重采样用 resample_poly（多相滤波），避免 librosa 的重采样缓存坑。

**Q8 怎么防止测试集泄漏？**
按说话人切分 train/test（VoiceBank 自带说话人不相交；DNS 子集要自己保证）；报告按说话人/噪声环境分组的指标模板——WP-09 的 evaluate_full 会做成 CSV + 分组透视。
