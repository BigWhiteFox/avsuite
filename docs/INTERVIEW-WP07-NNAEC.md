# INTERVIEW — WP-07 NN-AEC（模块7，简历核心项目）

## 3 分钟讲解提纲

**第 1 分钟：问题定义与输入输出**
- NN-AEC：mic = near + echo + noise，far 是回声的电信号参考；网络学 far→echo 的
  映射（含 RIR、功放非线性、时延漂移），输出近端语音
- 输入 4 通道：mic 复谱 Re/Im + far 复谱 Re/Im——far 参考让网络替代自适应滤波器
- 与传统 AEC 的关系不是取代而是级联/替代两种形态：微软 AEC-Challenge 冠军方案
  几乎都是"线性 AEC 先消 20dB + NN 消残余"；我们的 0.638M 模型走全 NN 路线，
  与 WP-06 传统基线同评估集直接对比

**第 2 分钟：架构与两个硬约束**
- 压缩 CRN：Enc 3 层因果复数卷积（F 257→33）→ 单向 LSTM(96) → 对称解码 + 跳连 → cRM
- 约束 1 参数 <1M（车机算力）：通道 [8,16,32]、频率维压缩后 LSTM 输入只有 1056
- 约束 2 时间严格因果（20ms 流式）：conv 左 pad、deconv 右移 2 帧、LSTM 单向——
  我用单测锁死：扰动未来输入，过去输出逐位不变。**因果性是测出来的不是声称出来的**

**第 3 分钟：数据与时延鲁棒（工程含金量最高的部分）**
- WP-07D 合成管道：真实语音 × RIR 池 × soft-clip(15%) × 10-80ms 随机时延 ×
  FEST/DT/NST 0.4/0.3/0.3，DT 带 1.5s 远端引导（真实通话时序）
- 训练期再对 far 加 ±10ms 帧级抖动——时延漂移是车载 AEC 第一杀手（蓝牙缓冲），
  评估有 ±5/10/20/40ms 衰减曲线
- 验收同口径三场景：FEST ERLE / DT 近端 PESQ / NST 透传，与传统基线对比表

## 高频追问预案

**Q1 为什么 far 参考直接进网络，而不先跑 NLMS 再让 NN 学残余？**
两条路线都存在：级联（线性+NN 残余）收敛稳、可解释、算力分摊——赛题冠军主流；
全 NN（我们的）结构简单、能学非线性、但吃数据且时延漂移敏感。我们选全 NN 是因为
①对比实验干净（同评估集 vs 纯传统）②0.638M 本来就小，级联反而复杂。面试加分答法：
"两条我都实现了"——级联实测结论（ADR 0005 及附记，eval_v5 DT n=154 稳健口径）：
DT echo 级联与纯 NN 统计打平（Δ+0.02 噪声级，早期 n=14 的 +0.17 系小样本波动）；
FEST echo 级联 4.589±0.05 三方最高；deg 纯级联不治（1.851≈1.811，病根在掩码结构
不在接口，距传统 2.43 恒差 ~0.6）。**生产形态=级联+近端门控（门控在研）**——线性级
吃长记忆与时延、NN 级吃非线性残余、近端保真靠门控直通补，而不是指望级联接口自己兜底。

**Q2 网络怎么处理时延？far 和 mic 没对齐它学得动吗？**
三层防御：①合成数据自带 10-80ms 随机时延（网络见过分布）；②训练期 ±10ms 抖动
（防过拟合到固定时延）；③架构上 LSTM 沿时间聚合 + conv 感受野 ~13 帧（260ms），
覆盖典型残余时延。评估：--jitter-sweep 给衰减曲线。生产系统仍建议前置粗对齐
（GCC-PHAT，WP-06 有现成实现）把时延压进感受野。

**Q3 cRM 输出对 AEC 合适吗？FEST 段目标近端是零，掩码学到什么？**
FEST 时 near=0 → 目标谱全零 → cRM 学出 ≈0 的掩码（全抑制）。这正是掩码范式的
好处：抑制深度无上限（谱减有音乐噪声地板）。风险是"过度自信置零"造成背景死寂——
我们用 γ 加权失真损失（近端响的 bin 罚重）+ 训练集 30% NST 样本保住"该透传时透传"。

**Q4 双讲为什么是 AEC 最难场景？NN 怎么赢传统？**
传统：DTD 必须冻结自适应（否则近端被学进回声路径）——冻结期间路径漂移无法跟踪，
且线性滤波器对"近端与回声同频带重叠"无能为力。NN：far/near 的区分不靠"冻结保护"
而靠学到的谱结构先验（语音谐波结构 vs 回声的 far 谱镜像），DT 段不需要任何冻结
逻辑。代价：对训练分布外的回声路径泛化风险——所以要 RIR 池多样化 + 上线前
目标车厢实测微调。

**Q5 0.638M 里参数都花在哪了？还能怎么压？**
LSTM(1056→96) 的输入矩阵占 ~65%（4×96×1056）。压缩路径：①频率维再压一层
（33→17，LSTM 输入减半）；②GRU 换 LSTM（-25%）；③FC 层用低秩分解；
④极致路线就是 GTCRN 的 ERB 压缩（WP-05a）——AEC 版 GTCRN 可以做到 <100K。
面试叙事："我知道每一块参数的去向和三条压缩路线"。

**Q6 训练目标为什么用 γ 加权失真而不是 SI-SNR/谱 MSE？**
AEC 的业务本质：近端语音保真 > 回声抑制深度（用户抱怨的是"我的声音被吃了"）。
γ 加权（w=|S_near|^γ）把损失注意力放到近端能量大的 T-F 单元——γ=0.5 近似响度域。
SI-SNR 做辅助项管波形级（--w-sisnr 默认 0.1，**主配置 v4 为 1.0**——提高波形级约束换
echo 收益，代价 deg 微降，见 README 探索矩阵 v1→v4）。消融开关 --gamma 0 直接对比（WORKLIST 要求的
γ 消融）。

**Q7 怎么评估？AECMOS 是什么？**
官方 AECMOS（微软，本地 ONNX：Run_1668423760）输出 **echo_mos / deg_mos 两路**——
SIG/BAK/OVRL 三分量是 DNSMOS 的输出，别混（WP02E 有对照表）。DT 场景 echo 管“回声漏没漏”、
deg 管“近端损没损”。官方长测试集须按协议裁剪送评（FEST 后半段 / DT 最后 (len−15)/2 s /
NST 全段），`exp/07_nn_aec/official_aecmos_eval.py` 已复刻官方链路（48k→16k 处理→48k 送评、
>20s 截断、逐条 rows 落盘）。自合成 8s 短片段为全段送评，绝对值与官方口径有差、同集对比
不受影响。对外 DT 数字一律带 95%CI（`tools/compute_ci.py`，汇总 `reports/DATA_CI.md`）。

集 +0.95、CI 不含 0；级联与纯 NN 统计打平（ADR 0005 附记）。近端保真是共同短板（三条 NN
路径 deg 全落 1.8 档 vs 传统 2.43），机理测量指向高频带选择性损伤与谱平坦化（reports/

**Q9 上生产还差什么？**
①流式 cache 化（WP-05b 模式：conv 时间 cache + LSTM state 外置）+ 流式/非流式
逐帧对齐测试；②ONNX/INT8（WP-05a 全链路方法学直接复用，注意 GRU/LSTM 静态
量化崩坏教训→动态或 QAT）；③目标车厢 RIR 实测微调 + 功放非线性数据增广（WP-08）；
④AECMOS 官方口径验收 + 长语音（分钟级）稳定性测试。

**Q10 时延漂移你们 NN 真的稳吗？**（V4 新增，判别实验）
分三层答：①漂移集实测（σ=5ms/s 游走、限幅 ±10ms）：NN 几乎不退（DT Δecho −0.19±0.29），
传统"一次对齐"管道崩塌（FEST −1.89，35/36 条降）——传统崩塌是零余量对齐+DTD 误冻的
实现缺陷（V4 已修：对齐余量+连续重估），非 MDF 本质；②**出窗即崩**：+110ms 时延 OOD
探针 NN DT echo 3.721→1.919（配对 Δ−1.802±0.125，154/154 全降、对 mic 地板余量
+2.18→+0.29）——NN 的稳健是**分布覆盖性**（训练失配窗 0–90ms），不是结构性的，早期
"逐帧映射不依赖对齐"的宣称已被自己的判别实验修正（reports/delay_ood_probe.md）；
③生产结论：NN 前必须保留 GCC 粗对齐把失配压回感受野（与漂移重训负结果 3.80→2.35
互证：靠数据覆盖换稳健是歧路）。

## 必默写
- 输入拼接：`X = [Re(Y_mic), Im(Y_mic), Re(Y_far), Im(Y_far)]`，输出 `cRM ⊙ Y_mic`
- 因果 deconv：对称转置卷积 out[t] 依赖 in[t-2..t+2] → 输出右移 2 帧因果化
- 三场景验收口径：FEST→ERLE（跳收敛段），DT/NST→近端 PESQ（对干净近端参考）
