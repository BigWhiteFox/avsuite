# INTERVIEW — WP-10.5 全链路 Capstone（选做·强烈建议）

## 3 分钟讲解提纲

**第 1 分钟：为什么是级联而不是一个大模型**
- 车载语音链 = 回声 + 噪声 + 混响三个正交问题，级联分解的工程理由：
  ①每级可独立调优/替换（AEC 换传统版、NR 换更大模型都不动架构）；
  ②时延账本可拆解（AEC 32ms + NR 32ms = 64ms，逐级可查）；
  ③失败可定位（是回声没消还是噪声没降，AECMOS 逐级分数直接回答）
- 微软 AEC-Challenge 冠军方案清一色级联——业界主流形态，不是我偷懒

**第 2 分钟：我的实现**
- AEC 级：WP-07 NN-AEC（0.638M，时间严格因果）跑在 WP-05b 流式引擎上，
  20ms 块进块出，离线等价 <1e-5 由单测锁死
- NR 级：GTCRN（23.67K，DNS3 官方权重）ONNX 整段批处理（官方 stream/ 版可切全流式）
- 演示：Gradio 三路 A/B 对比 + AECMOS 逐级分数——"每一级贡献多少"的量化证据

**第 3 分钟：量化叙事**
- 三级 echo_mos：1.5 → 3.5 → 3.5；deg 逐级变化——面试时现场跑 demo，
  比任何单个指标表都有说服力
- 端侧账本：AEC cache 270KB + GTCRN 290KB，全链路 <10MB——DSP 可落地

## 高频追问预案

**Q1 AEC 和 NR 为什么要分开？一个模型端到端做不行吗？**
可以（全 NN AEC+NR 联合），但代价：①联合训练数据要同时标注回声/噪声/混响三重
因素，合成配方复杂度爆炸；②单级失效无法定位（客户投诉"声音不对"，你没法回答
是哪一级的锅）；③时延与算力不可拆。工业界（微软冠军方案、车规供应商）全是级联。
我们仓库两条路都有（WP-07 全 NN AEC + 本 Capstone 级联），讲谱系完胜。

**Q2 级联的时延怎么算？**
AEC 32ms（窗长）+ NR 32ms（GTCRN 窗）+ 帧缓冲 ≈ 70-80ms 端到端，逐级可查。
若 NR 换流式版（官方 stream/），缓存共享后约 64ms。真实车规还要加蓝牙/功放链路
（100-300ms）——时延大头不在 DSP 而在无线链路，面试时点破这个加分。

**Q3 级联会不会误差传递？AEC 的伪影被 NR 放大？**
会，这正是级联设计的核心约束：AEC 输出是 NR 的输入，AEC 的掩码伪影（谱洞/
音乐噪声）会被 NR 当成噪声继续处理。缓解：①AEC 级宁欠勿过（我们 DT 保真的
损失设计就是这个意图）；②NR 的 g_min 地板保留残响；③中间级保留原始 mic 做
旁路监控。我们单测断言"NR 级不回退 echo 指标"就是防这个。

**Q4 demo 上传两路音频，现场演示怎么不翻车？**
预案：①预录三组 eval_v3 片段（DT/NST/FEST 各一）兜底；②网络断→本地模型全部
本地加载（无云端依赖）；③AECMOS 下载失败→只出波形对比（代码已容错）。

## 必默写
- 级联账本：`总时延 = Σ 各级（窗长 + 缓冲）`；我们：32+32+缓冲
- 三级指标叙事：`echo_mos 1.5 → 3.5`（每级贡献可指认）
